## Why this matters

Most real data is **many values at once**: a list of names, coordinates, unique tags, or a user profile with fields. Python has four collection types you will study in depth later. Here is a **map** so you recognize them early.

## list — ordered, changeable

A **list** holds items **in order**. You can **change** it (add, remove, update).

<PythonExample
  filename="list_preview.py"
  code={`names = ["Bini", "Sara", "Alex"]
print(names)
print(type(names))`}
/>

## tuple — ordered, unchangeable

A **tuple** holds items **in order** but is **fixed** after creation (immutable).

<PythonExample
  filename="tuple_preview.py"
  code={`point = (10, 20)
print(point)
print(type(point))`}
/>

## set — unique, unordered

A **set** holds **unique** items. Order is not the main idea — duplicates disappear.

<PythonExample
  filename="set_preview.py"
  code={`unique_numbers = {1, 2, 3, 2, 2}
print(unique_numbers)
print(type(unique_numbers))`}
/>

The extra `2` values are not stored twice.

## dict — key-value pairs

A **dict** (dictionary) maps **keys** to **values** — like a labeled record.

<PythonExample
  filename="dict_preview.py"
  code={`user = {"name": "Bini", "age": 25}
print(user)
print(type(user))`}
/>

## All four in one glance

<PythonExample
  filename="four_collections.py"
  code={`names = ["Bini", "Sara"]
point = (10, 20)
unique_numbers = {1, 2, 3}
user = {"name": "Bini", "age": 25}

print(type(names))
print(type(point))
print(type(unique_numbers))
print(type(user))`}
/>

## Recap

- **list** — ordered, changeable **`[...]`**
- **tuple** — ordered, fixed **`(...)`**
- **set** — unique items **`{...}`** (not empty `{}` dict)
- **dict** — keys and values **`{"key": value}`**
