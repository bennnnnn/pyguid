## Why this matters

Real programs often have **missing** data: no middle name, user not found, function that did not return anything useful. **`None`** is Python’s special value for “nothing here yet.”

## None means no value

**`None`** is a value that means **no value** / **not set** / **not found**.

<PythonExample
  filename="none_basic.py"
  code={`middle_name = None
print(middle_name)
print(type(middle_name))`}
/>

Output:

```text
None
<class 'NoneType'>
```

## None is not 0, not "", not False

| Value    | Meaning              |
| -------- | -------------------- |
| `None`   | no value             |
| `0`      | number zero          |
| `""`     | empty text           |
| `False`  | boolean no           |

They are **different types**. In an **`if`** test, `None`, `0`, `""`, and `False` are all **falsy** (act like “no”) — but they **mean different things**.

<PythonExample
  filename="compare.py"
  code={`print(None == 0)
print(None == "")
print(None == False)`}
/>

All print **`False`** — None is only equal to None.

## Used when something has no result yet

Functions with **no `return`** give **`None`** to the caller:

<PythonExample
  filename="no_return.py"
  code={`def say_hi():
    print("Hi!")

result = say_hi()
print(result)`}
/>

Output ends with **`None`** — the function ran, but did not **return** a value.

## Check with is None

<PythonExample
  filename="is_none.py"
  code={`value = None

if value is None:
    print("No value yet")`}
/>

Prefer **`value is None`** over **`value == None`** in real Python style.

## Recap

- **`None`** = no value; type is **`NoneType`**
- Not **`0`**, not **`""`**, not **`False`**
- Missing **`return`** → **`None`**
- Test with **`is None`**
