## Why this matters

**Inline comments** let you jot a quick **why** right where the action happens — without adding extra lines that break your reading flow.

## Same line: code first, then `#`

<PythonExample
  filename="inline_age.py"
  code={`age = 25  # example age for the lesson
print(age)`}
/>

Python assigns **`25`** to **`age`** and prints it. **`# example age…`** does nothing except explain to humans.

## Another everyday pattern

<PythonExample
  filename="inline_tax.py"
  code={`price = 100
discount = 0.2  # 20% off for demo
final = price * (1 - discount)
print(final)`}
/>

Only the arithmetic runs; **`# 20% off…`** documents the assumed discount.

<Callout variant="tip">
  If the comment only repeats what the variable name already says (`x = x + 1  # add one`), delete the comment or improve the names instead.
</Callout>

## Recap

- **Inline comment** = code, then **`#`**, then your note — same line
- Python executes **everything before** **`#`** on that line
- Prefer comments that explain **why** or **non-obvious context**, not obvious **what**
