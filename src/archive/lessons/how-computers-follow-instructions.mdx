## Why this matters

If you know **order matters**, half of beginner bugs make sense: “Why did that variable not exist yet?” — because the line that creates it has not run.

Think of a recipe: you cannot frost a cake before it is baked. A computer is the same with code.

## One step after another

<PythonExample
  filename="steps.py"
  code={`print("Step 1")
print("Step 2")
print("Step 3")`}
/>

**Output is always**

```text
Step 1
Step 2
Step 3
```

Python does not reorder your lines for fun. It starts at the **top** and moves **down** (for now, that is the full story).

## Later lines can use earlier work

<PythonExample
  filename="greet.py"
  code={`message = "Hi"
print(message)
print("Done")`}
/>

Line 1 must run before line 2. If you swapped them, Python would not know what `message` means yet.

<Callout variant="warning" title="Common mistake">
  Changing the order of lines changes what happens. If output looks “wrong,” check whether you ran lines in the order you expect.
</Callout>

## The computer does not guess

Computers are **fast** and **literal**. They do not understand your goal — only the steps you wrote. That is why programming rewards clear, small steps.

Later chapters add **if**, **loops**, and **functions** so flow is not always straight down. Until then, assume **top to bottom**.

## Recap

- Programs run **line by line** from top to bottom
- **Order** decides what exists before it is used
- Run examples and **reorder lines** once to see the difference
