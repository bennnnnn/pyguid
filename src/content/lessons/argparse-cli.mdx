## Why this matters

CLI with argparse shows up throughout Modules and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.


`sys.argv` works, but users forget argument order. **`argparse`** builds a **help message**, **flags**, and **typed** options — like `--count 3` instead of guessing positions.

## One new idea: ArgumentParser

<PythonExample
  filename="argparse_demo.py"
  code={`import argparse

parser = argparse.ArgumentParser(description="Say hello")
parser.add_argument("name", help="Who to greet")
parser.add_argument("--loud", action="store_true", help="SHOUT")

# Simulated parse (local: args = parser.parse_args())

args = parser.parse_args(["Ada", "--loud"])

message = f"Hello, {args.name}"
if args.loud:
message = message.upper()
print(message)`}
/>

**Line by line**

- `ArgumentParser` — defines your CLI
- `add_argument("name")` — required positional
- `--loud` with `store_true` — flag (False unless present)

## Local usage

```bash
python greet.py Ada --loud
python greet.py --help
```

`--help` prints usage automatically.

| Feature    | argparse gives you      |
| ---------- | ----------------------- |
| `--help`   | auto-generated          |
| `--flag`   | optional switches       |
| `type=int` | convert strings to ints |

## Recap

- **`argparse.ArgumentParser()`** + **`add_argument`**
- **`parse_args()`** returns an object with attributes
- Better UX than raw **`sys.argv`**
