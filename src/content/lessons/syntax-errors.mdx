## Why this matters

Syntax errors shows up throughout Print, Comments, and Errors and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

You typed a text message with a missing closing quote — your phone underlines it. Python does the same with **syntax errors**: the grammar of the code is broken **before** the program can run.

## One new idea: Python stops and points at the problem

<PythonExample filename="broken.py" code={`print("Hello"`} />

Run it. You will see something like **SyntaxError** — often mentioning a missing `)` or `"`.

**What it means in plain English**

| Message hint     | You probably forgot |
| ---------------- | ------------------- |
| `unexpected EOF` | closing `)` or `"`  |
| `invalid syntax` | typo, wrong symbol  |

Python is **not** broken. Your **line** needs a small fix.

## Fix and run again

<PythonExample filename="fixed.py" code={`print("Hello")`} />

**Before → after**

| Broken          | Fixed            |
| --------------- | ---------------- |
| `print("Hello"` | `print("Hello")` |

## Real habit: read the last lines first

Error output often shows:

```text
  File "example.py", line 1
    print("Hello"
                ^
SyntaxError: ...
```

1. **Line number** — where to look
2. **`^` caret** — roughly where Python got confused
3. **Error type** — `SyntaxError` = grammar, not logic yet

<Callout variant="danger" title="Oops — Python is yelling">
  Do not panic. Every programmer sees syntax errors **daily**. Fix one character, run
  again.
</Callout>

## Recap

- **Syntax errors** = code cannot run yet — usually a typo
- Read the **line number** and the **caret**
- Fix, run again — that is normal workflow
