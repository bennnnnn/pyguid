## Why this matters

insert shows up throughout Lists and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

**`append()`** only adds at the **bottom**. **`insert()`** is like sliding a new song **into the middle** of a playlist — everything after that spot shifts right.

## One new idea: `insert(index, item)`

<PythonExample
  filename="insert.py"
  code={`colors = ["red", "blue", "green"]
colors.insert(1, "yellow")
print(colors)`}
/>

**Before → action → after**

| Index | Before    | After `insert(1, "yellow")` |
| ----- | --------- | --------------------------- |
| `0`   | `"red"`   | `"red"`                     |
| `1`   | `"blue"`  | `"yellow"` ← new            |
| `2`   | `"green"` | `"blue"` (shifted)          |
| `3`   | —         | `"green"` (shifted)         |

Result: `["red", "yellow", "blue", "green"]`

**Line by line**

- `insert(1, "yellow")` — at index **`1`**, put **`"yellow"`**
- Items that were at index `1` and higher move one slot right

## Put something at the very start

<PythonExample
  filename="insert_start.py"
  code={`tasks = ["email", "meeting"]
tasks.insert(0, "standup")
print(tasks)`}
/>

Index **`0`** is always the front.

## At the end? Prefer append()

`insert(len(items), x)` works, but **`append(x)`** is simpler for the last slot.

<PythonExample
  filename="insert_end.py"
  code={`nums = [1, 2, 3]
nums.insert(3, 4)
print(nums)`}
/>

Index `3` is valid here — it means “after the last item,” same idea as append.

## Common mistake: negative index confusion

<Callout variant="warning" title="Oops — Python is yelling">
  **`insert(-1, x)`** inserts **before** the last item, not after it. For the true end,
  use **`append(x)`**.
</Callout>

## Recap

- **`insert(i, item)`** adds at position **`i`** and shifts the rest
- **`insert(0, x)`** — front of the list
- **`append(x)`** — end of the list (simpler than `insert` at the end)
