## Why this matters

**Syntax errors** happen **before** your program logic runs — so they are scary fast feedback. Learn the vocabulary once (`SyntaxError`, caret `^`), and fixing them becomes predictable.

## Broken grammar: missing closing parenthesis

<PythonExample filename="broken_hello.py" code={`print("Hello"`} />

Run it. Python reports **SyntaxError** — it expected **`)`** to close `print(...)`.

## The same idea, repaired

<PythonExample filename="fixed_hello.py" code={`print("Hello")`} />

One **`)`** made the grammar complete.

## Table: what SyntaxError feels like out loud

| What you typed      | Plain English hint                    |
| ------------------- | ------------------------------------- |
| `print("Hello"`     | Missing **)** (or stray quote)       |
| `print(Hello"`      | Unbalanced `"` quotes                |
| `print("Hello")` OK | Matches `(` … `)` and `"` … `"` pairs |

Syntax is about **balancing symbols** Python needs to parse the instruction.

## Unclosed or mismatched quotes

<PythonExample filename="bad_quote.py" code={`print("Hello)`} />

Python expected the closing **`"`** before the **`)`**. Every opening quote needs a matching closing quote on the same string.

## Wrong capitalization in names

Python treats spelling **exactly**. **`Print`** and **`print`** are different — only lowercase **`print`** is the built-in function:

```python
Print("Hi")   # NameError or invalid — not the real print()
print("Hi")   # correct
```

## Recap

- **Syntax errors** = invalid **structure** — code never starts running
- Typical beginner causes: missing **`)`**, **`"`**, or wrong punctuation placement
- Fix the **matching pairs**, run again—the message includes a **line number** clue
