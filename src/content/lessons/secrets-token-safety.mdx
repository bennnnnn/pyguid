`random` is fine for games. **Passwords, session tokens, and reset links** need **`secrets`** — cryptographically strong randomness from the standard library.

## One new idea: token_hex

<PythonExample
  filename="secrets_demo.py"
  code={`import secrets

token = secrets.token_hex(16)
print("Session token:", token)
print("Length:", len(token))`}
/>

`token_hex(16)` → 32 hex characters (16 bytes of randomness).

## Compare modules

| Module    | Use for                  |
| --------- | ------------------------ |
| `random`  | games, shuffling quizzes |
| `secrets` | passwords, tokens, keys  |

## Safe password-style string

<PythonExample
  filename="token_url.py"
  code={`import secrets

reset_link = secrets.token_urlsafe(12)
print(reset_link)`}
/>

URL-safe characters for links in emails.

<Callout variant="danger" title="Oops — Python is yelling">
  Never use **`random.randint`** for security. Attackers can guess weak tokens.
</Callout>

## Recap

- **`secrets.token_hex`**, **`token_urlsafe`**
- Store tokens in **environment variables**, not repos
- Pair with **os.environ** for config
