## Why this matters

else and finally shows up throughout Error Handling and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

**`try` / `except`** has optional teammates: **`else`** runs when **no** error happened; **`finally`** runs **always** — cleanup time.

## One new idea: else and finally

<PythonExample
  filename="else_finally.py"
  code={`def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("Cannot divide by zero")
        return
    else:
        print("Division OK:", result)
    finally:
        print("Done with divide")

divide(10, 2)
print("---")
divide(10, 0)`}
/>

| Block     | When it runs           |
| --------- | ---------------------- |
| `try`     | first — risky code     |
| `except`  | if matching error      |
| `else`    | if **no** error in try |
| `finally` | **always**             |

## Real use case: close a resource

```python
try:
    f = open("data.txt")
    data = f.read()
except OSError:
    print("File missing")
finally:
    print("Cleanup runs either way")
```

With **`with open(...)`** you often skip manual close — `finally` still matters for other resources.

## Recap

- **`else`** — success path after `try`
- **`finally`** — always runs
- Use for cleanup and clear structure
