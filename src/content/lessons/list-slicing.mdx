## Why this matters

Slicing lets you grab headers, tails, every other item, or reverse a sequence in one expression. It reads constantly in data cleaning and string-like list work. Slices return new lists (usually), so they pair well with sorting and copying patterns.

You do not always need the whole list — sometimes just the **middle slice**. **`[start:end]`** cuts a piece; **`end` is not included**.

## One new idea: slice a list

<PythonExample
  filename="slice.py"
  code={`nums = [0, 1, 2, 3, 4, 5]
print(nums[1:4])
print(nums[:3])
print(nums[2:])
print(nums[:])`}
/>

| Slice   | Result              |
| ------- | ------------------- |
| `[1:4]` | `[1, 2, 3]`         |
| `[:3]`  | first three         |
| `[2:]`  | from index 2        |
| `[:]`   | **copy** whole list |

## Common mistake: index vs slice

<Callout variant="warning" title="Oops — Python is yelling">
  **`nums[3]`** — one item. **`nums[1:3]`** — items at index 1 and 2 only. Off-by-one at
  the **end** trips everyone up.
</Callout>

## Recap

- **`[start:end]`** — end excluded
- **`[:]`** — shallow copy
- Same rules as string slicing
