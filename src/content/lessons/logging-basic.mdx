## Why this matters

Logging basics shows up throughout Python Standard Library and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.


`print` works until you need **timestamps**, **severity**, or **files** of history. The **`logging`** module is the standard way to record what your program did — and what went wrong.

## One new idea: getLogger and levels

<PythonExample
  filename="logging_demo.py"
  code={`import logging

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("myapp")

log.debug("Detail only for developers")
log.info("Server started")
log.warning("Disk almost full")
log.error("Could not save file")`}
/>

| Level     | When to use              |
| --------- | ------------------------ |
| `DEBUG`   | verbose development info |
| `INFO`    | normal milestones        |
| `WARNING` | odd but not fatal        |
| `ERROR`   | something failed         |

With `level=INFO`, **debug** lines are hidden.

## Log to a file (local)

```python
logging.basicConfig(
    filename="app.log",
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
)
```

## print vs logging

| print             | logging                       |
| ----------------- | ----------------------------- |
| quick experiments | real apps and servers         |
| always shows      | levels and files              |
| hard to filter    | turn down noise in production |

<Callout variant="tip">
  Replace stray debug prints with **`log.debug`** as projects grow.
</Callout>

## Recap

- **`logging.getLogger(__name__)`**
- **Levels** filter noise
- **`basicConfig`** for simple scripts
