Hospital triage labels: **broken bone**, **fever**, **allergy**. Exception **names** tell you what went wrong so you can fix the right thing — and write better `except` blocks.

## One new idea: ValueError

Wrong **value**, right type:

<PythonExample
  filename="value_error.py"
  code={`try:
    int("abc")
except ValueError as e:
    print("ValueError:", e)`}
/>

**Line by line**

- `int("abc")` — `"abc"` is text, but not a number-shaped string
- `ValueError` — the type does not fit the operation
- `as e` — store the error message in `e`

## TypeError — wrong type for the operation

<PythonExample
  filename="type_error.py"
  code={`try:
    result = "5" + 5
except TypeError as e:
    print("TypeError:", e)`}
/>

## IndexError and KeyError

<PythonExample
  filename="index_key.py"

print(items[10])
except IndexError:
print("Bad list index")

try:
print(data["z"])
except KeyError:
print("Bad dict key")`}
/>

## Real use case: validate before you trust

<PythonExample
  filename="raise.py"
  code={`def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

try:
set_age(-1)
except ValueError as e:
print(e)`}
/>

You can **`raise`** your own errors when rules are broken.

## AttributeError

<PythonExample
  filename="attr.py"
  code={`text = "hello"
try:
    text.append("!")
except AttributeError:
    print("Strings have no append — use + or join")`}
/>

<Callout variant="tip">
  Read the **last line** of a traceback first — it often states the exception type and
  message. Scroll up for the line number in your file.
</Callout>

<Callout variant="note">
  In development, letting an error crash can be fine — you fix the bug. In apps for users,
  catch expected errors and show helpful messages.
</Callout>

## Chapter 14 mini project: input validator

Handle several exception types in one small helper:

<PythonExample
  filename="validator.py"
  code={
    '# Mini project: safe parsing\nscores = {"Ada": "95", "Ben": "oops", "Cara": "88"}\n\ndef parse_score(name, data):\n    try:\n        return int(data[name])\n    except KeyError:\n        print(f"No score for {name}")\n        return None\n    except ValueError:\n        print(f"Bad score for {name}: {data[name]!r}")\n        return None\n\nfor name in ["Ada", "Ben", "Cara", "Dan"]:\n    score = parse_score(name, scores)\n    if score is not None:\n        print(f"{name}: {score}")'
  }
/>

Add a bad key or a non-number string. See which `except` runs.

## Recap

- **ValueError** — wrong value; **TypeError** — wrong type
- **IndexError / KeyError** — bad list index or dict key
- **`raise`** — signal your own rule violations
