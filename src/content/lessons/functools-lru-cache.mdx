## Why this matters

Caching with lru_cache shows up throughout Advanced Functions and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

Fibonacci with recursion recalculates the same numbers forever. **`@lru_cache`** remembers results so repeated calls return instantly — a memoization decorator from **`functools`**.

## One new idea: @lru_cache

<PythonExample
  filename="fib.py"
  code={`from functools import lru_cache

@lru_cache
def fib(n):
if n < 2:
return n
return fib(n - 1) + fib(n - 2)

print(fib(10))
print(fib.cache_info())`}
/>

Second call with the same `n` hits the cache.

## When it helps

| Good cache candidate    | Poor cache candidate    |
| ----------------------- | ----------------------- |
| pure function           | depends on global state |
| same args → same result | huge argument objects   |
| expensive compute       | fast already            |

<Callout variant="warning">
  Cached functions keep arguments in memory. Use **`maxsize=`** on huge inputs if needed.
</Callout>

## Recap

- **`from functools import lru_cache`**
- Decorate expensive **pure** functions
- Inspect **`cache_info()`** while learning
