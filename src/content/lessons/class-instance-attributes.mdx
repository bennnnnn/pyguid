## Why this matters

Instance vs class attributes shows up throughout Object-Oriented Python and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

Every student gets their **own** notebook (`self.name`). The classroom **bulletin board** is shared (`species = "Canis"` on the class). **Instance** attributes belong to one object; **class** attributes belong to the blueprint.

## One new idea: self vs class body

<PythonExample
  filename="dog_attrs.py"
  code={`class Dog:
    species = "Canis familiaris"

    def __init__(self, name):
        self.name = name

buddy = Dog("Buddy")
bella = Dog("Bella")
print(buddy.name, buddy.species)
print(bella.name)
print(Dog.species)`}
/>

- **`species`** on the class — same for all dogs
- **`self.name`** in `__init__` — unique per dog

## Shared class attribute trap

<PythonExample
  filename="trap.py"
  code={`class Team:
    members = []

    def add(self, person):
        self.members.append(person)

a = Team()
b = Team()
a.add("Ada")
print("Team a:", a.members)
print("Team b:", b.members)`}
/>

Both teams share **one** list! Mutable class attributes are a common bug.

<Callout variant="tip">
  Put mutable data in **`__init__`**: `self.members = []`, not on the class.
</Callout>

## Recap

- **`self.attr`** — per instance
- **`Class.attr`** — shared (great for constants)
- Never share **mutable** lists/dicts on the class body

See also: **`__init__` and self**, **`__str__` / `__repr__`**, **`super()`**.
