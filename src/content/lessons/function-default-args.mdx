## Why this matters

Defaults make APIs friendlier—optional flags, sensible starting values, and fewer required parameters. The mutable default list bug is a classic interview and production footgun. Learning safe defaults early prevents shared-state surprises across calls.

A coffee order defaults to “medium” unless you say “large.” **Default parameters** let callers skip arguments you already filled in.

## One new idea: name=default in def

<PythonExample
  filename="defaults.py"
  code={`def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}")

greet("Ada")
greet("Ben", "Hi")`}
/>

| Call                | `greeting` used |
| ------------------- | --------------- |
| `greet("Ada")`      | `"Hello"`       |
| `greet("Ben","Hi")` | `"Hi"`          |

## Real use case: power function

<PythonExample
  filename="power.py"
  code={`def power(base, exponent=2):
    return base ** exponent

print(power(5))
print(power(5, 3))`}
/>

<Callout variant="warning" title="Oops — Python is yelling">
  Put parameters **with defaults after** parameters **without** defaults: **`def f(a,
  b=1):`** not **`def f(a=1, b):`**.
</Callout>

## Recap

- **`param=default`** in `def`
- Caller can omit that argument
- Defaults go **at the end** of the parameter list
