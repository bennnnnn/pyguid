## Why this matters

Users and files are unpredictable—bad input, missing files, and network glitches happen. try/except lets you fail gracefully instead of dumping a traceback on beginners. It pairs naturally with input conversion and grows into logging and finally blocks.

A seatbelt does not stop accidents — it keeps you safe when one happens. **`try` / `except`** lets your program catch problems and keep going instead of crashing.

## One new idea: try and except

When something goes wrong, Python raises an **exception**. Without handling, the program stops.

<PythonExample
  filename="try_basic.py"
  code={`try:
    result = 10 / 0
except ZeroDivisionError:
    print("Cannot divide by zero")

print("Program continues")`}
/>

**Line by line**

- `try:` — run risky code
- `except ZeroDivisionError:` — if **that** error happens, run this block
- Code after the block still runs

## Catch a specific error

<PythonExample
  filename="value_error.py"
  code={`text = "hello"
try:
    number = int(text)
except ValueError:
    print("Not a valid number")`}
/>

## Real use case: safe division

<PythonExample
  filename="multiple.py"
  code={`def safe_divide(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return None
    except TypeError:
        return None

print(safe_divide(10, 2))
print(safe_divide(10, 0))`}
/>

Return `None` or a message instead of letting the crash reach the user.

## else and finally

- **`else`** — runs if no exception occurred
- **`finally`** — always runs (cleanup)

<PythonExample
  filename="else_finally.py"
  code={`try:
    value = int("42")
except ValueError:
    print("Bad input")
else:
    print("Parsed:", value)
finally:
    print("Done")`}
/>

<Callout variant="warning">
  Do not use bare `except:` that catches everything unless you re-raise or log — it hides
  bugs. Catch specific exception types.
</Callout>

<Callout variant="tip">
  Use try/except around risky operations: parsing user input, division, file access,
  network calls.
</Callout>

## Recap

- **`try` / `except`** — catch expected errors
- Catch **specific** types — `ValueError`, `ZeroDivisionError`, etc.
- **`else` / `finally`** — success path and cleanup
