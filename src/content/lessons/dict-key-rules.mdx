## Why this matters

Dictionary key rules shows up throughout Dictionaries and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

Dict keys are like **locker labels** — they must be **unique** and **unchangeable** (immutable) so Python can find the locker fast.

## One new idea: valid keys

<PythonExample
  filename="keys.py"
  code={`user = {
    "name": "Ada",
    42: "answer",
    (1, 2): "tuple key"
}
print(user["name"])
print(user[42])
print(user[(1, 2)])`}
/>

| Key type | OK? | Why                               |
| -------- | --- | --------------------------------- |
| `str`    | yes | immutable                         |
| `int`    | yes | immutable                         |
| `tuple`  | yes | immutable (if contents immutable) |
| `list`   | no  | mutable → **TypeError**           |

<Callout variant="danger" title="Oops — Python is yelling">
  **`{[1, 2]: "x"}`** fails — lists cannot be keys. Use **tuple** instead:
  **`{(1, 2): "x"}`**.
</Callout>

## Keys must be unique

<PythonExample
  filename="unique.py"
  code={`scores = {"math": 90, "english": 85}
scores["math"] = 95
print(scores)`}
/>

Second `"math"` **updates** — does not create two math keys.

## Recap

- Keys: **unique**, **immutable**
- **`str`** and **`int`** are common keys
- **`list`** cannot be a key
