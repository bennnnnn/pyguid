Imagine you are packing a box and you write **socks** on the outside. Next time you need socks, you open the box labeled **socks** — you do not hunt through everything again.

In Python, a **variable** is that label. The **name** is on the left; the **value** is on the right.

## One new idea: assignment with `=`

The **`=`** sign **assigns** a value. It does **not** mean “equals” in math class (that is `==`, later).

<PythonExample filename="step1.py" code={`age = 25`} />

**Line by line**

- `age` — the variable name you chose
- `=` — “store this value under this name”
- `25` — the number being stored

Read it aloud: “**age is 25**.”

## See what you stored

<PythonExample
  filename="step2.py"
  code={`age = 25
print(age)`}
/>

`print(age)` looks inside the label **age** and shows `25`.

## Text needs quotes

Words are **strings** — wrap them in quotes:

<PythonExample
  filename="text.py"
  code={`name = "Ada"
print(name)`}
/>

<Callout variant="warning" title="Oops — Python is yelling">
  `name = Ada` without quotes makes Python think **Ada** is a variable name. If Ada does
  not exist yet, you get a **NameError**. Quotes mean “this is text.”
</Callout>

## Two variables, one program

<PythonExample
  filename="two.py"
  code={`city = "London"
year = 2024
print(city)
print(year)`}
/>

Each line creates **one** label. `print` can use any label you already created.

## Common mistake: swapping sides

Writing `25 = age` is **invalid**. The **name** must be on the **left**, value on the **right**.

<TryIt title="Try it yourself" answer="Hello, PyGuide">
  Create a variable `message` with the text `Hello, PyGuide`, then `print(message)`.
</TryIt>

## Recap

- A variable is a **name** for a **value**
- Use **`=`** to assign
- Use **`print(name)`** to show what is stored
- Put **text in quotes**; leave **numbers** without quotes
