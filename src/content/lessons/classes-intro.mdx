## Why this matters

Classes bundle data and behavior—users, bank accounts, game sprites. Even script-heavy Python eventually uses objects from libraries built on classes. Understanding **init**, self, and attributes makes Django, pytest fixtures, and dataclasses approachable.

A cookie cutter is the **blueprint**; each cookie is an **instance**. A **class** is the blueprint; an **object** is one thing built from it — with its own data and actions.

## One new idea: class and object

<PythonExample
  filename="class_basic.py"
  code={`class Dog:
    pass

buddy = Dog()
bella = Dog()
print(buddy)
print(bella)`}
/>

**Line by line**

- `class Dog:` — define a type named `Dog`
- `buddy = Dog()` — create an **object** (instance)
- Two calls → two separate dogs

## **init** sets up each object

<PythonExample
  filename="init.py"
  code={`class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

buddy = Dog("Buddy", 4)
print(buddy.name)
print(buddy.age)`}
/>

`self` refers to the **current object**. Python passes it automatically.

## Real use case: user profile

<PythonExample
  filename="attrs.py"
  code={`class User:
    def __init__(self, username):
        self.username = username
        self.active = True

u = User("ada_lovelace")
print(u.username)
u.active = False
print(u.active)`}
/>

Name and status belong together on one object — not scattered variables.

<Callout variant="note">
  `self` must be the first parameter of instance methods. Python passes the object
  automatically when you call `buddy.bark()`.
</Callout>

<Callout variant="tip">
  Use a class when several values belong together (a user, a product, a bank account) and
  share behavior.
</Callout>
