Sometimes **you** know the input is invalid before Python trips on its own. **`raise`** stops the program flow and reports an error — like **`except`** in reverse.

## One new idea: raise an exception

<PythonExample
  filename="raise_demo.py"
  code={`def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    print("Age set to", age)

set_age(25)
try:
set_age(-1)
except ValueError as e:
print("Caught:", e)`}
/>

**Line by line**

- `raise ValueError("...")` — create and throw an error
- Caller can **`except ValueError`** like any other error

## Real use case: guard early

<PythonExample
  filename="guard.py"
  code={`def withdraw(balance, amount):
    if amount > balance:
        raise ValueError("Not enough money")
    return balance - amount

print(withdraw(100, 40))`}
/>

<Callout variant="warning">
  Do not **`raise`** for normal control flow (like skipping loops). Use **`if`** /
  **`return`** when no error is involved.
</Callout>

## Recap

- **`raise`** — report a problem
- Pick a **sensible type** (`ValueError`, etc.)
- Pair with **`try` / `except`** where you call risky functions
