A recipe card says “mix eggs and flour” once — you follow it every time you bake. A **function** is that card for code: write the steps **once**, **call** the name whenever you need them.

## Why functions matter

Without functions, programs become long copy-paste scripts. When requirements change, you hunt every duplicate block. Functions give you:

- **Reuse** — one definition, many calls
- **Names** — `price_with_tax()` reads better than ten loose lines
- **Testing** — check one function in isolation
- **Team work** — each function is a small contract

Professional Python (L4 path) assumes you reach for functions before repeating logic three times.

## One new idea: def and call

<PythonExample
  filename="hello_func.py"
  code={`def greet():
    print("Hello from a function")

greet()
greet()`}
/>

**Line by line**

- `def greet():` — define a function named `greet`
- Indented lines under `def` — the body runs only when you **call** it
- `greet()` — run the function (twice here)

Defining a function does **not** run its body. Only the **call** does.

## Pass data in with parameters

<PythonExample
  filename="params.py"
  code={`def greet(name):
    print(f"Hello, {name}")

greet("Ada")
greet("Lin")`}
/>

`name` is a **parameter** — a placeholder filled in when you call `greet("Ada")`.

## Multiple parameters

<PythonExample
  filename="multi.py"
  code={`def add(a, b):
    print(a + b)

add(3, 5)
add(10, 20)`}
/>

## Real use case: one place to change

<PythonExample
  filename="tax.py"
  code={`def price_with_tax(amount):
    tax = amount * 0.08
    return amount + tax

print(price_with_tax(10))
print(price_with_tax(25))`}
/>

If the tax rate changes, you edit **one function** — not every calculation in your program.

## Common mistakes

<Callout variant="danger" title="Oops — Python is yelling">
  **IndentationError** — every line in the function body must use the **same** indent
  (usually 4 spaces). The line after `def` cannot start at column 0.
</Callout>

<Callout variant="warning">
  **Calling before defining** — Python must see `def greet():` before `greet()`. Put
  definitions above calls (or import from another module later).
</Callout>

| Mistake                      | Fix                                                |
| ---------------------------- | -------------------------------------------------- |
| Forgot `()` on call          | `greet` references the function; `greet()` runs it |
| No `return` but need a value | use `return` (next lessons)                        |
| Same code in three places    | extract one `def`                                  |

## FAQ

**What is the difference between a parameter and an argument?**  
In `def f(x):`, `x` is a **parameter**. In `f(5)`, `5` is an **argument** passed at call time.

**Can a function call itself?**  
Yes — that is **recursion** (covered in advanced topics). Start with simple non-recursive functions.

**Do I need `return` on every function?**  
No. Functions without `return` give back `None`. Use `return` when callers need a value — see **Return values**.
