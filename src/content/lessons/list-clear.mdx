## Why this matters

clear shows up throughout Lists and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

You erase every line on a whiteboard but the board is still there. **`clear()`** removes **all** items; the list variable still exists — it is just **empty**.

## One new idea: empty the list in place

<PythonExample
  filename="clear.py"
  code={`nums = [1, 2, 3, 4, 5]
nums.clear()
print(nums)
print(len(nums))`}
/>

**Before → action → after**

| Before            | After `clear()` |
| ----------------- | --------------- |
| `[1, 2, 3, 4, 5]` | `[]`            |
| `len` = 5         | `len` = 0       |

Returns **`None`**, like `append` and `remove`.

## Real use case: reset a shopping cart

<PythonExample
  filename="cart_reset.py"
  code={`cart = ["milk", "bread", "eggs"]
print("Before checkout clear:", cart)

cart.clear()
print("After clear:", cart)
print("Items:", len(cart))`}
/>

## clear() vs `a = []` — shared references matter

Two names can point at the **same** list:

<PythonExample
  filename="same_reference.py"
  code={`a = [1, 2, 3]
b = a
a.clear()
print("a:", a)
print("b:", b)`}
/>

Both **`a`** and **`b`** see **`[]`** — same object, now empty.

Assigning **`a = []`** makes **`a`** a **new** empty list; **`b`** still holds the old data:

<PythonExample
  filename="new_list.py"
  code={`a = [1, 2, 3]
b = a
a = []
print("a:", a)
print("b:", b)`}
/>

<Callout variant="tip">
  Use **`clear()`** when other variables must see the list become empty. Use **`a = []`**
  when only **`a`** should forget the old list.
</Callout>

## Recap

- **`clear()`** removes every item; list is **`[]`**
- Same list object — other references see the empty list too
- **`a = []`** is different when **`b`** still pointed at the old list
