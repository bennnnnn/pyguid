## Why this matters

Before Python syntax, it helps to know what you are actually doing: **giving instructions**. Every lesson in PyGuide builds on that one idea.

**Programming** means writing those instructions in a form a computer can follow. You are not “talking to the computer in English.” You are describing **exact steps** to reach a goal.

## Everyday examples

| Task | Instructions (in plain English) |
| ---- | ------------------------------- |
| Make tea | Boil water → pour over bag → wait → remove bag |
| Morning alarm | If weekday and time is 7:00 → play sound |
| Sort photos | For each file → if name ends with `.jpg` → move to folder |

Those steps are a **program** in human language. Code is the same idea, written more precisely.

## What programmers do

1. **Understand the problem** — What should happen? What is input? What is output?
2. **Plan steps** — Often on paper first.
3. **Write code** — In a language like Python.
4. **Run and test** — See if the computer does what you meant.
5. **Fix mistakes** — Errors are normal; you adjust and run again.

You do not need advanced math to start. You need **clear thinking** and patience.

## How this connects to Python

Python is one way to write those steps. The next lessons explain **code**, how computers **run lines in order**, and why **Python** is a strong first language.

## Recap

- **Programming** = step-by-step instructions for a computer
- **Program** = those steps written down
- **Your job** = be precise; computers follow what you wrote, not what you meant
