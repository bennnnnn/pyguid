Code tells the computer **what to do**. **Comments** tell **humans** why — they are notes Python **does not run**.

## One-line comments

Start a comment with `#`:

<PythonExample
  filename="comments.py"
  code={`# This is a comment — Python skips it
print("This line runs")`}
/>

## Comments at the end of a line

<PythonExample filename="inline.py" code={`print(10 + 5)  # adds 10 and 5`} />

Everything after `#` on that line is ignored.

## What to write in comments

Good comments explain **why**, not obvious **what**:

<PythonExample
  filename="why.py"
  code={`# Sales tax rate for the example region
tax_rate = 0.08
price = 50
print(price * tax_rate)`}
/>

<Callout variant="tip">
  Clear variable names (`tax_rate`, `price`) often reduce the need for comments. Comment
  when the reason is not obvious from the code alone.
</Callout>

## What comments cannot do

Comments do not turn off code inside strings:

<PythonExample
  filename="in_string.py"
  code={`print("Hello # this is still part of the text")`}
/>

The `#` above is printed — it is **inside** the quotes.

## Comment out code temporarily

Developers often “comment out” a line to test without deleting it:

<PythonExample
  filename="disable.py"
  code={`print("Version A")
# print("Version B")
print("Done")`}
/>

Only **Version A** and **Done** print.

<Callout variant="danger" title="Do not break strings">
  Starting `"` and commenting in the middle of a string without closing quotes causes a
  **syntax error**. Finish or close the string first.
</Callout>
