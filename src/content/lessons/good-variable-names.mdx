## Why this matters

Python allows many legal names—but **good** names explain what a value **means**. Future-you (and teammates) read code more than they write it; clear names are free documentation.

## Clear beats cryptic

**Bad** — legal, but confusing:

```python
x = "Bini"
a = 25
```

**Better** — says what you stored:

<PythonExample
  filename="clear.py"
  code={`user_name = "Bini"
user_age = 25
print(user_name, user_age)`}
/>

When you see **`user_age`**, you know it is an age—not “some number called `a`.”

## snake_case for multiple words

Python style for variable names is **snake_case**: lowercase words joined with **`_`**.

<PythonExample
  filename="snake.py"
  code={`first_name = "Alex"
last_name = "Lee"
full_name = first_name + " " + last_name
print(full_name)`}
/>

Read **`first_name`** as “first name,” not **`firstname`** mashed together.

## When short names are OK

Single letters like **`i`** or **`x`** appear in tiny loops or math-style snippets. For beginners learning real programs, prefer **`score`**, **`total`**, **`file_path`** until the meaning is obvious from context.

<Callout variant="tip">
  Ask: “If I read this line in a month, will I know what this value is?” If not, rename it.
</Callout>

## Recap

- Use **clear** names that describe the data
- Use **snake_case** for multi-word names
- Avoid random **`x`** / **`a`** unless the value is truly temporary
