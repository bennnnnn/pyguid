## Why this matters

If you know Python reads **top to bottom**, many beginner bugs make sense: “Why does that name not exist yet?” — because that line has not run.

## Lines run in order

<PythonExample
  filename="order.py"
  code={`print("First")
print("Second")
print("Third")`}
/>

**Output is always**

```text
First
Second
Third
```

Python does not skip or reorder lines on its own. (Later, `if` and loops change flow — not yet.)

## Order matters when one line needs another

<PythonExample
  filename="right_order.py"
  code={`name = "Bini"
print(name)`}
/>

Line 1 runs first and creates `name`. Line 2 can use it.

**Wrong order** — run this on purpose:

<PythonExample
  filename="wrong_order.py"
  code={`print(name)
name = "Bini"`}
/>

Python stops with **NameError**: `name` does not exist when `print(name)` runs.

<Callout variant="warning" title="Common mistake">
  Put the line that **creates** a value **above** the line that **uses** it. You will practice variables properly in the Variables chapter; the rule is the same.
</Callout>

## Math before print (preview)

<PythonExample filename="math.py" code={`print(3 + 4)`} />

Python evaluates `3 + 4` **first**, then passes `7` to `print`. Small expressions inside `print()` are fine from day one.

## Blank lines are for you

<PythonExample
  filename="spacing.py"
  code={`print("Start")

print("End")`}
/>

Empty lines are ignored — they separate ideas for human readers.

## Recap

- Python runs from the **top** of the file **down**
- **Order** decides what exists before it is used
- Fix order errors by moving the **create** line above the **use** line
