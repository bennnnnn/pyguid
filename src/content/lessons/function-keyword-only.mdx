## Why this matters

Keyword-only parameters shows up throughout Advanced Functions and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

Some settings are dangerous to mix up — host vs port vs TLS. **Keyword-only** parameters must be passed **by name**, so `connect("api.example.com", port=443)` is clear and `connect("api.example.com", 443)` is not allowed.

## One new idea: star in the parameter list

<PythonExample
  filename="kwonly.py"
  code={`def connect(host, *, port=443, timeout=30):
    print(f"Connecting to {host}:{port} (timeout {timeout}s)")

connect("api.example.com", port=8080)
connect("api.example.com", timeout=5)`}
/>

The bare **`*`** in the definition means: everything **after** it is keyword-only.

## What happens if you break the rule?

```python
connect("api.example.com", 8080)  # TypeError
```

Python refuses positional args for `port` and `timeout`.

## Signature order (reference)

```python
def f(pos1, pos2, /, pos_or_kw, *, kw_only1, kw_only2=10):
    ...
```

| Part           | How to pass       |
| -------------- | ----------------- |
| Before `*`     | position or name  |
| After `*` only | **name required** |

<Callout variant="tip">
  Use keyword-only for optional flags (`debug=True`, `ssl=True`) on functions with many
  parameters.
</Callout>

## Recap

- **`*`** in `def` → following params are keyword-only
- Prevents confusing argument order
- Pairs with `*args` / `**kwargs` on advanced APIs
