## Why this matters

Environment variables (os.environ) shows up throughout Modules and later chapters. Understanding it here makes the next lessons easier and helps you read real Python code with confidence. PyGuide keeps each page focused on one idea so you can practice without getting lost.

Apps store API keys and database URLs in **environment variables** — not hard-coded in source. **`os.environ`** is a dict-like map of names to values your OS provides.

## One new idea: read a variable

<PythonExample
  filename="environ.py"
  code={`import os

# Simulated environment (your shell sets these for real)

os.environ["APP_NAME"] = "PyGuide"
os.environ["DEBUG"] = "true"

print(os.environ["APP_NAME"])
print(os.environ.get("DEBUG", "false"))
print(os.environ.get("MISSING", "default"))`}
/>

Use **`.get`** with a default when the variable might be missing.

## Set locally (terminal)

```bash
export APP_NAME=PyGuide
python app.py
```

Windows PowerShell:

```powershell
$env:APP_NAME = "PyGuide"
```

## Why not hard-code secrets?

| In source code    | In environment        |
| ----------------- | --------------------- |
| leaks in git      | stays on your machine |
| same for everyone | different per deploy  |

<Callout variant="warning">
  Never commit `.env` files with real passwords. Add `.env` to `.gitignore`.
</Callout>

## Recap

- **`import os`** → **`os.environ`**
- **`.get(name, default)`** for safe reads
